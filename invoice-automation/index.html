The problem

Invoices arrive by email. Someone types them in by hand.

Small businesses in the UAE, such as restaurants, cafés and clinics, receive invoices from suppliers as PDF attachments. Someone has to open each one, read the supplier, invoice number, dates and amounts, and type them into a spreadsheet. It is slow, it is easy to make mistakes, and nobody notices when an invoice is missing information, paid twice, or overdue.

I worked in data entry for a year, so I know this job well. This project automates it.

What the AI does

From a PDF to clean, structured data

The AI reads the invoice text and returns the same nine fields every time. It converts dates to one format, removes commas from amounts and picks a spending category, even though the invoice never states one.

Design decisions

Why it is built this way

Code does the maths, AI does the writing

Language models can make arithmetic mistakes. A JavaScript node calculates every total, percentage and due date. The AI only turns those exact numbers into a readable report, and the prompt tells it not to recalculate.

The AI is told not to guess

The extraction prompt says to leave a field empty when it is not on the invoice. An If node then checks for a number, a date and a total above zero. Incomplete invoices go to a person instead of into the books.

No invoice is saved twice

The sheet uses Append or Update matched on the invoice number. If the same invoice is emailed again, the existing row is updated and no duplicate is created, so the same bill is never counted or paid twice.

Failures are reported, not hidden

A separate error workflow emails the workflow name, the node that failed, the error message and a direct link to the failed run, so problems are found in minutes.
